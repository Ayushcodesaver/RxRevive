{{ macros.icon('spark') }} Project Overview

RxRevive is an intelligent web-based system that analyzes candidate resumes and job descriptions using Natural Language Processing. It identifies relevant skills, measures compatibility, calculates matching scores and generates detailed suitability reports — through two independent NLP implementations of the same problem.

{{ macros.icon('doc') }} Common Problem Statement

“Develop an intelligent web-based system that analyzes candidate resumes and job descriptions using Natural Language Processing (NLP) to identify relevant skills, measure compatibility, calculate matching scores, compare candidate profiles with job requirements and generate detailed suitability reports.”

{{ macros.icon('x') }} Existing System Limitations

  • {{ macros.icon('x') }} Manual resume screening is slow, subjective and inconsistent
  • {{ macros.icon('x') }} Keyword-only ATS filters miss qualified candidates who use different wording
  • {{ macros.icon('x') }} Candidates receive no feedback on why they don't match a role
  • {{ macros.icon('x') }} Single-method systems are never compared against alternatives

{{ macros.icon('layers') }} Proposed System

A unified platform where the same inputs flow through two engines:

  • {{ macros.icon('check') }} Traditional NLP — TF-IDF vectorization + cosine similarity (lexical)
  • {{ macros.icon('check') }} Transformer NLP — Sentence-BERT embeddings (semantic)
  • {{ macros.icon('check') }} Shared skill taxonomy, identical weighting and output schema for fair comparison

{{ macros.icon('target') }} Project Objectives

  1. Automate resume–job compatibility analysis with explainable scores
  2. Implement and contrast lexical vs semantic NLP on identical data
  3. Provide matched/missing skill intelligence to candidates
  4. Generate professional, downloadable suitability reports
  5. Maintain rigorous honesty: no fabricated metrics, clear disclaimers

{{ macros.icon('brain') }} Research Motivation & NLP Technology

Resume matching is a natural testbed for the lexical-vs-semantic question in NLP. TF-IDF represents the vector-space tradition — interpretable and cheap. Sentence-BERT represents modern transformer architectures — contextual, paraphrase-aware, heavier. Building both on one problem lets us quantify what semantic understanding actually buys.

{{ macros.icon('layers') }} System Architecture (summary)

Flask application factory + blueprints · SQLAlchemy ORM over SQLite · two swappable NLP engines behind one schema · ReportLab PDF generation · Chart.js visualisation. The full diagram is on the Architecture page.

{{ macros.icon('check') }} Expected Outcomes

  • {{ macros.icon('check') }} Demonstrable semantic advantage of SBERT on paraphrased content
  • {{ macros.icon('check') }} Quantified score differences across both engines on identical inputs
  • {{ macros.icon('check') }} A reusable evaluation pipeline for the labelled Resume-Job Fit dataset
